# Raw Model · 重点演示稿讲者备注

## 01 AI 最底层的 Raw Model

从开场的连续提问进入课程。说明本课沿原讲解建立底层抽象，之后才进入模型服务。

### 对应完整讲解

它知不知道什么叫自然语言？它知不知道你说的话是什么意思？它知不知道什么叫中文、什么叫英文？它知不知道？你看它的输入输出就完事了。它输入的是个啥？这是中文吗？这是英文吗？这是图片吗？这是视频吗？这是啥？

好，各位同学，咱们今天聊的是 Raw Model，我把它翻译成为“裸模型”。裸模型是整个 AI 技术体系的最底层，就是无论你用什么样的 AI 技术，最终你都是用的它——裸模型。

其实有些资料里边用的是另外一个词，叫“基础模型”，或者把 Raw Model 翻译成“原始模型”。其实无所谓。我把它翻译成“裸模型”，就是告诉同学们：这一块剥离了任何花里胡哨的功能，看到 AI 最本质的真相，就是这个东西。

而且这一块的技术，在原理上或者知识体系上是非常稳定的。从那个 2023 年 GPT-3.5 出来到现在，它就没变过，一直是这么一套技术体系。

这个模型到底是啥呢？简单理解，它就是一个函数：接收一个输入，产生一个输出。输入是啥？输入我们把它叫做 Token 列表。什么叫 Token 列表？你可以把它想象成一个数字的数组。

## 03 语言先变成数字

强调“平均”二字，没有半个 Token。保留词根、前缀的例子。数组仅为课堂示意。

### 对应完整讲解

比方说，数字就是这么一个东西：2、3、4、5、1、8。数字有可能很大。那这个 Token 到底是什么东西？它就是我们的自然语言换算成数字的结果。至于怎么换算，你暂时不用管，这个东西叫做分词。

一般来说，我们中文平均一个字能分出 1.5 个 Token。注意，是平均下来。你说哪有半个 Token？其实没有。有的中文可能就是一个 Token，有的可能两个 Token，甚至三个 Token。平均下来，中文就是 1.5 个 Token。也就是一个字约等于 1.5 个 Token。

那么英文呢？英文一个单词，大概分出来是 1.3 个 Token，大概这样。但每个单词分出来可能不一样，比如有词根，还有前缀，都可能进行划分。

最终，我们给裸模型一个消息，这个消息会先进行分词，把它分成一个个 Token，就会形成一串数字。

### 画面与校读说明

便笺列出数字数组 [2,3,4,5,1,8]，并写有“中文：1个字≈1.5 token”“英文：1个单词≈1.3 token”。左侧输入标为 Token List。比例是本课使用的近似估算口径。

## 04 输出是一组可能性

按原课先给15的0.7，再给288的0.2。不要把输出的分布直接说成已经选出的字，也不在本课补讲采样算法。

### 对应完整讲解

把这串数字喂给或者说传递给裸模型，它得到的是什么？得到的是一个概率分布。什么概率分布？就是下一个 Token 的概率分布。

得到的大概是这么一个数据结构，用一个对象表示：你给了它一串数字，它得到的是下一个数字有哪些可能性。比如说 15，可能性为 0.7，也就是 70%；下一个 Token 是 288 的可能性为 0.2。它把各种可能性排列起来，这就是裸模型，没了。

裸模型就是做一套数学计算，就在做这么一个事：算出下一个 Token 的概率分布。这跟我们平时用的模型，或者一些 AI 工具，感觉差别特别特别大，对吧？因为这是最底层的东西。上层怎么利用它玩出那些花样，我们后边再说。最核心的东西没了，裸模型就这样子。

你说这个玩意儿有什么意义？你想，这些数字跟我们的自然语言有对应关系。比如中文，一个数字可能对应半个或者一个中文。这些数字串起来，会串成自然语言，对不对？它返回的下一个 Token，是不是也是自然语言的一部分？比如这一串得到的自然语言可能是“你好”，下一个数字可能表示一个逗号，也有可能表示“吗”，是不是这个意思？

### 画面与校读说明

模型输出箭头标为“概率分布”。便笺展示 15:0.7、288:0.2 等候选项，旁边出现“你好”的续写示例；这些是教学示意，并非某个实际模型的实测概率。

## 06 上下文窗口有多长？

原课用长度100和容量一万却传入两万的截断案例来建立直觉。“不会报错、自动截断”是原课表述，不能作为所有接口行为的保证。

### 对应完整讲解

那就是往后边猜测下一个词到底是啥，或者下一个字到底是啥。这个图同学们一定要记住，这就是裸模型最原始的状态。

后边还有很多平时蛮常见的术语，我给大家解释一下：这些术语在这个图里面对应哪个地方。第一个就是“上下文窗口”，叫 Context Window。这是什么？非常简单，你只要知道这个图，就很好解释：它指的就是这个 Token 列表的长度，就这么简单。

比方说，这个数组的长度为 100，那么目前的上下文窗口就是 100。平时我们说，新发布的一个模型支持最大的上下文窗口多少多少，是什么意思？就是它最大能支持多长的输入长度。超过这个长度它就受不了了，它也不会给你报错，就把前面的东西截断。比如只支持一万的上下文窗口，结果你传了两万，前面的一万它就不要了，自动扔掉。这就是最大的上下文窗口。

目前一般的上下文窗口，128K 是比较常见的。这个 K 不是说占了什么磁盘空间，跟磁盘空间没有关系；K 表示千。算出来是 12.8 万，就是这个数组的长度最大可以是 12.8 万。

你可以想一想，12.8 万换成中文，可以容纳多少个字？平均一个文字占 1.5 个 Token，我们就估算一下：128,000 除以 1.5，大概就是八万多个中文字符。除了 128K，还有 256K，还有 1M，一兆。注意，这不是磁盘空间；一兆指的是一百万，million。

如果是 1M，支持多少中文字符？除以 1.5，就支持大概六十六万个中文字符。也就是说，这个函数能处理的最大的 Token 数量，就是上下文窗口，好理解了吧？

不过有一个特性要给同学们说一下：上下文窗口指的是它能装得下的 Token 数量，最大能够处理多少个 Token，并不代表它能够把这些东西处理好。现在 AI 也是有泡沫的，同学们都知道，大模型之间的竞争也比较激烈。

## 08 装得下 ≠ 处理得好

保留两条代码规则的原始例子。继续解释原课为何提到子代理：用独立上下文处理任务。这里是讲者对使用现象的解释，不宣称所有遗忘都只有同一个原因。

### 对应完整讲解

各大厂商为了让自己的模型有卖相，不停地给你堆参数，可能结果你用下来不是那么回事。什么意思？比如它支持 1M 的上下文窗口，指的是 Token 列表长度能够容纳一百万。但是你把这些东西扎扎实实扔进去之后，会发现好多东西根本处理不过来。

同学们平时用 AI，有没有发现一个现象？刚开始打开一个新的窗口，跟它聊天，觉得它挺聪明，你说啥它都记得住。当你聊了很多之后，会发现它变傻了，之前一些规则忘了。明明说好每次写完代码要提交，它把这个规则忘了；明明说好一个代码文件、一个模块不能超过 200 行代码，它写的时候就忘了。

为什么？这就是上下文窗口的问题。虽然它能够容纳这么多 Token，但是它记不住。弄了很多之后，模型能力会下降。这提示我们，模型原生有这么一个特性，所以平时用模型，那些相对独立的事情，尽量新开上下文窗口去做。

后面我们还会讲一些工具的使用，你会发现它会用很多子代理。为什么要用子代理？就是来处理这个问题。这是第一个概念，叫上下文窗口。

第二个，我们到模型这一部分来。目前把它看成一个函数。实际上它是不是函数？实际上它不是函数，它是什么？它是一个矩阵。应该说，这个函数是我们自己写的。

## 09 下载的模型，核心是权重

区分函数抽象与下载文件。原课提到几个G、几十G、几百G乃至一个T的体积，但参数个数与存储字节不是同一个单位。

### 对应完整讲解

实际上这个函数里面在调用一个矩阵。这里我用一个双向箭头，把它叫做“权重矩阵”。我跟你们说一下到底怎么回事：实际上我们的模型是这个东西。

有些同学可能在本地部署过模型。本地部署的时候，是不是要把模型下载到本地？下载的实际上是啥？就是这个矩阵。当然还有一些其他的配置文件，比如 config 之类，不过核心就是这个矩阵。

矩阵是啥？就是一串数字，超级多的数字。下载模型时你会发现，有些模型几个 G、几十个 G、几百个 G，甚至一个 T。主要占空间的，就是这个矩阵，数字超级多。

我们平时经常说，这个模型有多少参数，那个模型有多少参数，指的是什么？就是矩阵里面数字的数量。比方说一个模型有 7B，B 是什么？billion，十亿。7B 就是七十亿个参数。换句话说，矩阵里面有七十亿个数字，简单吧？

一般本地模型是 7B、16B，不会太大。但是一些商用级的，放到专用推理服务器上，那些模型的参数就比较大。目前有超过一个 T 的——不是一个 T，是十个 T。我记得什么 GPT-5 还是什么模型，是超过十个 T 的，十万亿以上的参数。T 就是万亿，指矩阵里面有十万亿个数字。

我们平时说的模型训练，指的是什么？就是得到这样一个矩阵的过程。训练的目的是什么？生成一个权重矩阵。至于它怎么训练，如何得到这个矩阵、里面是什么意思，是大模型工程师，也就是算法工程师要考虑的事情。跟咱们没关系，你只需要知道这个概念。

## 13 架构规定怎样使用权重

原课提及通过Hugging Face库调用模型，并强调训练架构与调用方式相配。板书另写“Tensor架构”，所指没有明确展开，完整教程保留，讲授时不要把它补充成已验证的架构分类。其他AI技术不一定适用这一套描述。

### 对应完整讲解

训练的结果就是这个权重矩阵。严格来说，裸模型是啥？裸模型是一个矩阵，它不是一个函数。但是模型要用，你不能光把这些数字给我，我怎么用？因此一般会通过 Hugging Face 的一个库去调用模型。

调用方式要看你用什么样的模型架构。目前最常见的是什么架构？来，大声告诉我，就是 Transformer 模型架构。你可以用 Transformer 这个架构，它里面可以提供一个函数去调用这个矩阵。

如果用另外一些架构，比如 Tensor，那就用 Tensor 里面提供的函数去调用矩阵，懂那个意思吧？不同架构使用矩阵的方式不一样。一般来说，训练的时候基于什么架构来训练，就要用什么架构来调用。

比如现在用的大模型都是基于 Transformer 架构训练的，训练出来的权重矩阵，肯定要用 Transformer 架构调用。用别的架构能不能调用？如果要调用，就要对矩阵做一些转换，就是这套模式。

### 画面与校读说明

便笺上写有“Transformer架构”和“Tensor架构”。这里忠实保留原课的术语及说法；Tensor 的具体所指没有展开，不把它补写成经核实的另一种模型架构。

## 14 先建立数学函数的直觉

继续复述原课的1+2=3类比和对AI拟人化的评论。将“自我意识、感情”等保留为原讲者观点；单凭函数形式不展开哲学结论。本页讲计算结果，不把它等同于完整聊天系统每次的文字回答。

### 对应完整讲解

顺便多说一句，这套模式属于神经网络和深度学习，它们使用这种方式。如果用机器学习之类其他的 AI 技术，可能就不是这套模式了。我们现在讲的是基于神经网络和深度学习的模式。不扯远了，因为目前基本上玩的都是 Transformer。

这一块再总结一下：你传入一个 Token 列表，传给这个函数。这个函数是基于 Transformer 架构的函数，拿到 Token 列表之后要进行一段运算。运算过程就是使用矩阵里面的参数，也就是各种各样的数字，再结合输入，加上算法，得到概率分布的结果。

所以大模型的本质是啥？从技术上讲，是一个数学函数，甚至可以认为它是个纯函数——不是可以认为，它就是个纯函数。Token 列表一定，得到的结果就不变化。

## 15 GPU 计算还要面对浮点数

参数多、运算量大，因此使用GPU并行计算。原课解释拆分、计算、合并，并以浮点不满足结合律说明误差。保留讲者关于旧知识在新场景里派上用场的感想。

### 对应完整讲解

你输入 1、2、3，它就得到 4。我随便举几个例子，输入不变，得到的结果就不变。再说得吓人一点，它跟这个东西没有什么区别：纯函数，输入 1 加 2 等于 3。只不过公式没有这么简单，是一个比加法更复杂的公式，得到一个结果。

所以你看网上有些人都开始崇拜 AI 了，快形成宗教了。什么“AI 要统治全人类”“AI 开始出现自我意识”“AI 开始对人类发脾气”，你看一下这个东西就行了。他天天膜拜的是啥？膜拜的是一个函数，就是我们高中课本里面一个公式。他说那个玩意开始出现感情了，我也不知道这个东西能有啥感情。它就是数学运算，传入什么得到什么，而且是纯函数，不会变化。

当然，理论上是纯函数，实际上可能没有那么纯。原因不是函数不是纯函数，函数还是纯函数，只是在运行的时候经过 GPU。因为参数量太大，要计算的数学运算太多，因此需要通过 GPU 并行运算。它把数学公式进行拆解，拆解后运算，最后合并，大概这个意思。

由于 GPU 是并行运算，就会导致一个问题。计算机世界里使用浮点数，没问题吧？浮点数不满足结合律。什么意思？我给你们举个例子，放大一点：0.1 + 0.2 + 0.3，它有误差，对不对？再看另外一个，很神奇，0.1 + (0.2 + 0.3)，就没有这个显示出来的误差了。

你看，它不满足结合律。在计算机浮点数的世界里，前面这个等于后面这个吗？你会发现它不等于。至于为什么，以前我有一个抖音短视频专门讲过，讲这种误差到底怎么来的。万万没想到在这里用上了。所以知识永远是有用的，你不知道将来会在哪里用上。

总之它不满足结合律。有什么问题？现在有一个很长的公式需要运算，一拆解，拆解位置不同，得到的结果就可能不一样。所以理论上是纯函数，实际上可能没有那么纯。

好，老有同学说：“袁老师，现在的模型不都是什么多模态模型吗？怎么解释多模态？”我告诉你，没有什么好解释的，一样的。

### 画面与校读说明

浏览器控制台完整显示：0.1+0.2+0.3 → 0.6000000000000001；0.1+(0.2+0.3) → 0.6；两式比较得到 false。这是浮点加法顺序的演示。“感情、自我意识”等评论属于原讲者观点，不能把函数示意视为对该议题的完整证明。

## 16 多模态，也先转成数字

保留原课“它知道什么叫自然语言吗”的重复提问，以及“里面没有那么简单”的限定。图像编号是随手举例，不是通用标准；讲者用字典区间和转码解释如何识别输出类型，不能推广成所有多模态模型的统一流程。

### 对应完整讲解

对这个东西来说，我问你，听到现在，它知不知道什么叫自然语言？它知不知道什么叫中文、什么叫英文？你好好想一想。

我再问一次：它知不知道什么叫自然语言？知不知道你说的话是什么意思？知不知道什么叫中文、什么叫英文？它知不知道？你看输入输出就完事了。它输入的是啥？这是中文吗？英文吗？图片吗？视频吗？这是啥？这是一个数字的数组，它哪知道这个数字是什么东西？它不知道。因为对它来说都是数字，它不知道那是什么。反正看到这个数字，经常后面会跟另外一个数字，它不知道那是什么意思。

这是很多人崇拜的、要产生自我意识的模型，就是这么个东西。因此什么多模态，什么图片、视频、音频、声音，对它来说没有区别，都是数字。经常训练，看到这个数字后面跟另外一个数字，就可以算出概率分布，就是这个意思。

当然里面没有那么简单，还有一些特别的东西，那是模型内部的东西，我们不扯远。总之基本上就是这个逻辑。音频也好、视频也好、图像也好，对它来说都是数字。你给它训练什么，它就能做什么。

只不过人拿到这个东西之后，要分辨一下。比如我这句话是“请帮我生成一张什么什么图片”，它吐出来一个 Token——不是一个 Token，是下一个 Token 的概率分布。那么我要判断，这个 Token 是文字还是图像。

其实也很好判断，因为 Token 是一个字典，有字典列表。比如它给我一个 500008，随便举的。我发现这个 Token 落在一个叫 image 范围的区间，原来知道它是跟图像相关的东西。那么就把它当成图像里面的信息，再进行转码、转换，得到一个图像可能某个像素点的信息，懂这个意思吧？好，就没啥了，裸模型认识到这里就够了。
